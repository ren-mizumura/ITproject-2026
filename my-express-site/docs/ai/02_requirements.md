# AI質問機能 要件定義書 (`02_requirements.md`)

## 1. 概要・スコープ

* **対象システム**: Express / TypeScript 製の既存 Web アプリケーション（`my-express-site/`）
* **実行基盤**: Vercel（サーバーレス環境） / Neon（PostgreSQL）
* **機能概要**: ユーザーが AI とチャット形式で質問・対話できる独立した AI 質問画面（`views/ai/index.ejs`）を新設する。会話履歴は Neon（DB）に永続化し、AI の回答は Markdown レンダリングで視認性高く表示する。
* **対象ユーザー**: 本アプリを利用する一般ユーザーおよび管理者
* **利用 AI・SDK・モデル**:
  * サービス: Gemini AI
  * SDK: `@google/genai`（公式 SDK）
  * 使用モデル: `gemini-3.5-flash-lite`
  * 環境変数: `GEMINI_API_KEY`
* **画面配置**: 既存の TODO 画面（`views/todo/index.ejs`）とは分離し、専用ルート（`/ai`）配下に独立ページとして配置する。

## 2. 機能要件

### 2.1. AI 質問画面（チャット UI）

* **画面表示**: `/ai` へのアクセスで `views/ai/index.ejs` をレンダリングし、チャット画面を表示する。
* **初期履歴読み込み**: 画面表示時、Neon（DB）に保存されている過去の会話履歴を取得し、時系列順に復元表示する。
* **構成要素**:
  * 会話履歴表示エリア（ユーザーの発言と AI の回答を視覚的に区別して表示）
  * 質問入力フォームおよび送信ボタン
  * 応答待機中のローディング表示（送信中インジケーター）
  * エラーメッセージ表示エリア
  * 会話履歴を初期化するリセットボタン（DB 上の履歴削除または新規会話開始）
  * 既存画面（TODO 画面など）へ移動できるナビゲーションリンク

### 2.2. チャット送受信・永続化・文脈保持

* **非同期通信**: フロントエンドからバックエンドへ質問テキストを非同期送信し、ページリロードなしで画面を更新する。
* **DB 永続化（Neon）**:
  * ユーザーからの質問および AI からの回答を、Neon 上に新設する専用テーブルへ永続化する。
  * ページリロードや再アクセス後も過去のやり取りを閲覧・継続できること。
* **文脈を踏まえた応答**:
  * バックエンドは Neon から直近の会話履歴を取得し、最新の質問とあわせて Gemini API（`gemini-3.5-flash-lite`）へ送信することで、文脈を踏まえた回答を生成する。
* **回答の Markdown レンダリング**:
  * AI からの回答テキストに含まれる Markdown 記法（見出し、太字、箇条書き、コードブロック、インラインコード等）を HTML に変換し、見やすく整形して表示する。
  * ユーザーの発言は意図しない記法変換やスクリプト実行を避けるため、プレーンテキスト（改行反映）として安全に表示する。
* **画面描画制御**: ユーザー送信時に発言を即時表示し、AI からの回答取得後に回答をレンダリング・追記して最新メッセージまで自動スクロールする。

### 2.3. 入力バリデーション・送信制御

* **空入力チェック**: 空文字または空白文字のみの送信をフロントエンド・バックエンド双方で拒否する。
* **文字数制限**: 1回の質問あたりの最大文字数（例: 2,000文字）を設け、超過時はエラーとする。
* **履歴送信上限**: トークン超過やレスポンス遅延を防ぐため、Gemini API に渡す会話コンテキストに上限（例: 直近 10 往復 / 20 メッセージ）を設ける。
* **二重送信防止**: AI 応答の待機中は送信ボタン・入力操作を制御し、連続クリックによる重複リクエストを防ぐ。

### 2.4. エラーハンドリング

* **入力エラー（400系）**: 入力値不正が発生した場合、具体的な原因が分かるユーザーフレンドリーなエラーメッセージを画面に表示する。
* **通信・API・DB エラー（500系 / タイムアウト / レート制限）**: Gemini API 通信失敗、API キー未設定、または Neon（DB）エラー発生時に、内部スタックトレースを露出せず分かりやすい案内メッセージを画面に表示する。
* **データ整合性**: Gemini API 呼び出しが失敗した場合、不完全な会話データが残らないよう保存タイミングやエラー時の扱いを適切に制御する。
* **サーバー安定性**: 非同期処理の例外を確実に捕捉し、サーバーがクラッシュしないよう既存のグローバルエラーハンドラーへ連携する。

## 3. 非機能要件

* **アーキテクチャ・既存規約の踏襲**:
  * 既存の TODO アプリ（`src/apps/todo/`：`todoRouter.ts` / `todoController.ts` / `todoModel.ts`）の設計パターンに倣い、`src/apps/ai/` 配下に Router / Controller / Model / Service を分離して実装する。
  * DB 接続は既存の `db.ts` を再利用する。
  * テーブル作成 SQL は既存規約（`sql/todo/020_create_todo_tasks.sql`）に倣い、`sql/ai/` 配下に配置する。
  * フロントエンド静的ファイルも既存規約（`public/todo/TodoApi.js`, `main.js`）に倣い、API 通信層と画面制御層の分離を意識して構成する。
* **セキュリティ・機密情報管理**:
  * API キー（`GEMINI_API_KEY`）や DB 接続情報はソースコードに直書きせず、`dotenv`（ローカル）および Vercel 環境変数（本番）からサーバー側のみで読み込む。
  * **XSS 対策（Markdown レンダリング）**: AI 回答を Markdown から HTML に変換する際、悪意のあるスクリプト実行を防ぐため必ずサニタイズ処理（例: `DOMPurify` の併用）を行う。
  * **SQL インジェクション対策**: Neon へのクエリ実行時は必ずパラメータ化クエリ（プレースホルダ）を使用する。
* **既存機能への非影響**:
  * 既存の TODO 機能、ルーティング、DB 接続、404 ハンドリング、エラーハンドリングを一切破壊しない。
* **Vercel サーバーレス環境への適合**:
  * サーバー側メモリに会話状態を保持せず、完全ステートレス（永続化はすべて Neon）で設計する。
  * Vercel Serverless Functions の実行時間制限を考慮し、高速応答な `gemini-3.5-flash-lite` を採用するとともに、適切なタイムアウトおよびフロントエンドの待機表示を備える。

## 4. 実装・配置スコープ（`my-express-site/` 配下）

| 区分 | ファイルパス / 項目 | 役割・内容 |
| :--- | :--- | :--- |
| **ルーティング** | `src/apps/ai/aiRouter.ts` | `/ai` 配下の画面表示およびチャット API のエンドポイント定義 |
| **コントローラー** | `src/apps/ai/aiController.ts` | リクエスト検証、レスポンス制御、エラー連携 |
| **モデル（DB）** | `src/apps/ai/aiModel.ts` | 既存 `db.ts` を用いた Neon 上の会話履歴 CRUD 処理 |
| **サービス（AI）** | `src/apps/ai/aiService.ts` | `@google/genai` を用いた `gemini-3.5-flash-lite` 呼び出しロジック |
| **SQL（DDL）** | `sql/ai/030_create_ai_messages.sql` | Neon 用 会話履歴テーブル作成 SQL（※名称・番号は設計時に確定） |
| **ビュー** | `views/ai/index.ejs` | チャット形式の AI 質問画面テンプレート |
| **静的ファイル** | `public/ai/AiApi.js` / `public/ai/main.js` | 非同期 API 通信、Markdown 描画・サニタイズ、DOM 制御 |
| **サーバー統合** | `index.ts` | ルーターのマウント（`app.use('/ai', aiRouter)`） |
| **パッケージ** | `@google/genai` | Gemini AI 公式 SDK（バックエンド） |
| **描画ライブラリ** | `marked` + `DOMPurify`（案） | フロントエンドでの Markdown 変換および XSS サニタイズ |
| **環境変数** | `GEMINI_API_KEY` | Gemini API 認証キー（`.env` および Vercel 環境変数に設定） |

## 5. 確定方針と次フェーズ（`03_design.md`）での詳細化項目

### 5.1. 確定済み方針

1. **会話履歴の保持方式**: Neon（PostgreSQL）に専用テーブルを追加して永続化
2. **使用 AI・モデル**: Gemini AI（`@google/genai`） / `gemini-3.5-flash-lite`（環境変数: `GEMINI_API_KEY`）
3. **回答表示形式**: Markdown レンダリング（XSS 対策としてサニタイズ処理を併用）
4. **画面構成**: TODO 画面とは独立した `views/ai/index.ejs` を `/ai` に配置

### 5.2. 設計フェーズ（`docs/ai/03_design.md`）で詳細化する項目

* **API エンドポイント体系**: 既存の `index.ts` / `todoRouter.ts` のパス規約に合わせた URL 設計（例: `GET /ai`, `GET /ai/api/messages`, `POST /ai/api/messages`, `DELETE /ai/api/messages` 等）
* **DB テーブル設計**: 会話履歴テーブルのカラム定義・インデックス設計、および会話の粒度（全アクセス共通の単一履歴とするか、セッション／スレッド ID 単位で分けるか）
* **リクエスト / レスポンス JSON スキーマ** およびエラーコード定義
* **Markdown レンダリング・サニタイズ方式**: CDN 読み込みとするかパッケージ管理とするかの選定
