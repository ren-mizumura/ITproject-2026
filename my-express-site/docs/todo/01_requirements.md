# TODOアプリ 要件定義書

## 1. 目的・対象範囲
本プロジェクトは、既存のExpress＋TypeScript＋EJS構成のWebサイトにTODOアプリ機能を追加することを目的とする。
既存の `/` および `/api/db-check` エンドポイントは維持し、新規の画面は `/todo` に配置する。
データストアには既存のNeon PostgreSQLを使用し、既存のDB接続および `DATABASE_URL` を流用する。ホスティング先はVercelとする。
REST APIのエンドポイントは `/api/v1/todos` とし、GET、POST、PATCH、DELETEの4操作を提供する。画面からの操作はFetch APIを通じてこれらを実行する。
なお、V1フェーズにおいては「認証」「優先度」「絞り込み」「タイトルの更新」機能はスコープ外とする。
※ フロントエンドの `TodoApi` クラス等へのモジュール分割や、具体的なファイル配置については本要件定義では「要確認」とし、詳細設計書にて定義する。

## 2. 4機能と受け入れ条件

### REQ-01: 一覧
- **操作**: ユーザーが `/todo` にアクセスした際、初期表示としてTODO一覧を取得・描画する。
- **入力**: なし
- **結果**: ステータス `200 OK`。レスポンスは `data` プロパティ内にTODOオブジェクトの配列（昇順）を返す。0件の場合は `data: []` を返す。
- **エラー**: 500, 503
- **受け入れ条件**: 登録済みのTODOが昇順で一覧表示されること。0件の場合でもエラーにならず空のリストとして処理されること。
- **確認方法**: ブラウザで `/todo` にアクセスし、データが正しく画面に表示されるか確認する。

### REQ-02: 登録
- **操作**: 画面の入力欄にTODOのタイトルを入力し、追加操作を行う。
- **入力**: `title`（前後の空白を除去した上で1〜100文字の文字列）
- **結果**: ステータス `201 Created`。レスポンスは `data` プロパティ内に作成されたTODOオブジェクトを返す。
- **エラー**: 400（必須キー欠落、型違い）, 422（文字数違反）, 500, 503
- **受け入れ条件**: 有効な文字数のタイトルが送信された場合、新規TODOが作成されて画面の一覧に追加表示されること。
- **確認方法**: 画面から新しいTODOを入力・送信し、一覧の末尾（または指定の昇順位置）に追加されるか確認する。

### REQ-03: 完了状態の部分更新
- **操作**: 画面の一覧上のチェックボックス等のUIを操作し、TODOの完了/未完了状態を切り替える。
- **入力**: パスパラメータに `id`（1以上の整数）、リクエストボディに `completed`（真偽値）を指定する。
- **結果**: ステータス `200 OK`。レスポンスは `data` プロパティ内に更新後のTODOオブジェクトを返す。
- **エラー**: 400（ID不正、型違い）, 404（対象不在）, 500, 503
- **受け入れ条件**: 指定したTODOの完了状態のみが更新され、画面上の表示状態が切り替わること。
- **確認方法**: 画面から既存のTODOの状態を変更し、チェック状態が正しく反映されるか、再読み込み後も状態が維持されるか確認する。

### REQ-04: 削除
- **操作**: 画面の一覧にある削除ボタン等のUIを操作する。
- **入力**: パスパラメータに `id`（1以上の整数）を指定する。
- **結果**: ステータス `204 No Content`。レスポンス本文はなし。
- **エラー**: 400（ID不正）, 404（対象不在）, 500, 503
- **受け入れ条件**: 指定したTODOが削除され、画面の一覧から該当項目が消えること。
- **確認方法**: 画面から既存のTODOを削除し、一覧から消失するか、再読み込みしても復活しないか確認する。

## 3. 共通のデータ・エラー条件
- **データ構造**:
  - `id`: 1以上の整数
  - `title`: 文字列（1〜100文字）
  - `completed`: 真偽値
  - `created_at`: 日時
  - `updated_at`: 日時
- **成功レスポンス**: POST（登録）およびPATCH（部分更新）の成功時も `{ "data": { ... } }` のJSON形式で単一のオブジェクトを返す。
- **エラーレスポンス**: エラー時は `{ "error": { "code": "...", "message": "..." } }` のJSON構造で返す。
- **エラーハンドリング (UI)**: エラー発生時は、画面内のエラーメッセージ領域にテキストとしてエラー内容を表示する。
- **ステータスコード基準**:
  - `400 Bad Request`: 不正なJSON構文、パスパラメータのIDが整数でない、必須キー欠落、型違い
  - `422 Unprocessable Entity`: 業務バリデーション違反（`title` が空文字、または101文字以上など）
  - `404 Not Found`: 操作対象のIDが存在しない
  - `500 Internal Server Error`: 予期せぬサーバー内部エラー
  - `503 Service Unavailable`: DB接続失敗、クエリタイムアウト等

## 4. 環境別確認
- Preview環境およびProduction環境は、同一のNeon DBを参照する構成とする。
- 本番・プレビュー環境ともに個人情報は一切扱わず、動作確認時は架空のダミーデータのみを使用して検証を行うこと。
